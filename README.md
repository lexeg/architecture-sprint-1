# Задание 1
## Уровень 1. Проектирование
Для создания микрофронтендов был выбран фреймворк Webpack Module Federation.
Причины следующие:
- Webpack Module Federation позволяет микрофронтендам динамически обмениваться зависимостями во время выполнения
- В проекте используется React и планов по использованию нескольких фреймворков одновременно нет
- Каждая команда может независимо собирать и деплоить свой микрофронтенд
- Больше экспертизы по данному фреймворку

## Уровень 2. Планирование изменений
Принято решение разбить монолитный фронтенд на следующие микрофронтенды:
* сервис аутентификации - вся логика по аутентификации/авторизации пользователей выделяется в отдельный сервис, позволяя независимо от остальной части приложения развивать новые способы аутентификации
* сервис для работы с карточками мест
* сервис для работы с профилями пользователей

### Целесообразность
* **Сервис аутентификации** - вся логика по аутентификации/авторизации пользователей выделяется в отдельный сервис, позволяя независимо от остальной части приложения развивать новые способы аутентификации
* **Сервис "Карточки мест"** - CRUD-операции с местом выделяются в отдельный сервис, позволяя хранить их в отдельной БД (DB per Service) и в случае увеличения нагрузки масштабировать
* **Сервис "Профиль пользователя"** - CRUD-операции по работе с профилем пользователя перенесены в отдельный сервис, позволяя работать с данными о пользователях отдельно от других частей приложения (например, карточек мест). Возможно, в будущем будет принято решение, что выделение в микрофронтенд избыточно, тогда не составит труда произвести объединение с сервисом аутентификации

# Задание 2
* **Authentication service** - сервис аутентификации. Отвечает за авторизацию/регистрацию пользователя
* **Goods service** - сервис товаров и услуг. Отвечает за все CRUD-операции с товарами/услугами, поиск и фильтрацию по ним.
* **Orders service** - сервис заказов. Занимается обработкой заказов.
* **Payments service** - сервис оплаты. Отвечает за все способы оплаты заказа, за проведение и отмену оплаты.
* **Notifications service** - сервис уведомлений (может быть как свой, так и сторонний). Занимается отправкой уведомлений об изменениях (новый пользователь, статус заказа, участников аукциона и тд)
* **Reports service** - сервис отчетов. Создает отчеты на основе данных сервисов аутентификации и оплаты
